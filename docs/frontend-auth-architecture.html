🔧 4. AuthService — core/services/auth.service.ts

É o único responsável por toda autenticação. Nenhum componente acessa localStorage diretamente — tudo passa por aqui.

Responsabilidades

Método / PropriedadeO que faz
login(request)POST para o BFF → salva tokens e user no localStorage → atualiza o signal
register(request)POST para o BFF → cria a conta (sem fazer login automático)
logout()Limpa localStorage → zera o signal → redireciona para /
getToken()Lê bandhub_token do localStorage — usado pelo interceptor
isAuthenticated()Retorna !!getToken() — usado pelos guards
user (signal readonly)Estado reativo do usuário logado — qualquer componente pode ler com authService.user()

Como o tap() funciona (RxJS)

login(request): Observable<LoginResponse> {
  return this.http
    .post<LoginResponse>(`${this.api.apiBaseUrl}/bff/accounts/login`, request)
    .pipe(
      tap(response => this.saveSession(response))
      // tap() executa um efeito colateral (salvar na sessão) SEM modificar o stream
      // O componente ainda recebe o LoginResponse normalmente no .subscribe()
    );
}

O que é salvo no localStorage

ChaveConteúdo
bandhub_tokenJWT access token (string)
bandhub_refreshRefresh token (string)
bandhub_userJSON com accountId, name, email, accountType
O signal _user é inicializado lendo o localStorage no construtor via this.loadUser(). Isso garante que, ao recarregar a página, o usuário continua logado sem precisar chamar a API novamente.

🛡️ 5. Interceptor — core/interceptors/auth.interceptor.ts

Intercepta toda requisição HTTP saindo da aplicação e injeta o token automaticamente. Você não precisa colocar o header manualmente em nenhum lugar.

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).getToken();

  if (token) {
    const authReq = req.clone({
      setHeaders: { Authorization: `Bearer ${token}` },
    });
    return next(authReq);  // envia a requisição MODIFICADA
  }

  return next(req);  // sem token → envia sem header (login, register)
};

Por que req.clone()?

Requisições HTTP no Angular são imutáveis. Você não pode alterar um HttpRequest diretamente. req.clone({ setHeaders: {...} }) cria uma cópia com os headers adicionados.

Diferença: Angular 8 vs Angular 15+ (funcional)

Angular 8Angular 15+ (este projeto)
Classe que implementa HttpInterceptor, registrada em HTTP_INTERCEPTORS Função pura (HttpInterceptorFn), registrada diretamente no provideHttpClient()
@Injectable + intercept(req, next) inject() diretamente na função, sem classe

🚧 6. Guards — core/guards/

Guards são funções que o Angular Router executa antes de ativar uma rota. Se retornarem false ou uma UrlTree, a navegação é cancelada/redirecionada.

authGuard — protege rotas privadas

export const authGuard: CanActivateFn = () => {
  const auth   = inject(AuthService);
  const router = inject(Router);

  // Token existe? Permite. Senão, redireciona para /login
  return auth.isAuthenticated() ? true : router.createUrlTree(['/']);
};

guestGuard — evita re-login desnecessário

export const guestGuard: CanActivateFn = () => {
  const auth   = inject(AuthService);
  const router = inject(Router);

  // Já logado? Vai direto pro dashboard. Senão, mostra o login
  return auth.isAuthenticated() ? router.createUrlTree(['/dashboard']) : true;
};

Diferença: Angular 8 vs Angular 14+ (funcional)

Angular 8Angular 14+ (este projeto)
Classe com @Injectable implementando CanActivate Função pura (CanActivateFn) com inject() dentro
canActivate(route, state): boolean (route, state) => boolean | UrlTree

⚙️ 7. app.config.ts — registro global

No Angular 17+ standalone (sem AppModule), tudo que era registrado no NgModule vai para o appConfig.

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideRouter(routes),

    // Registra HttpClient + o interceptor funcional
    provideHttpClient(
      withInterceptors([authInterceptor])
    ),
  ],
};
Por que provideHttpClient aqui?
No Angular 17+ standalone, se você não registrar o HttpClient no appConfig, qualquer inject(HttpClient) nos serviços vai lançar um erro em runtime. O withInterceptors([authInterceptor]) registra o interceptor funcional — substituindo o antigo HTTP_INTERCEPTORS do Angular 8.

🗺️ 8. app.routes.ts — rotas com guards

export const routes: Routes = [
  {
    path: '',
    canActivate: [guestGuard],          // logado? → /dashboard
    loadComponent: () => import('./features/login/login.component')
      .then(m => m.LoginComponent),
  },
  {
    path: 'dashboard',
    canActivate: [authGuard],           // sem token? → /
    loadComponent: () => import('./features/dashboard/dashboard.component')
      .then(m => m.DashboardComponent),
  },
  {
    path: '**',
    redirectTo: '',                     // qualquer rota inválida → login
  },
];
loadComponent (lazy loading) — o bundle do componente só é baixado quando o usuário navegar para aquela rota. Isso é importante para performance: o usuário não precisa baixar o código do dashboard se nem está logado.

Fluxo do onLogin()

onLogin() {
  if (this.loginForm.invalid) {
    this.loginForm.markAllAsTouched(); // exibe todos os erros de validação
    return;
  }

  this.loading.set(true);
  this.errorMessage.set(null);

  this.authService.login(request).subscribe({
    next: () => this.router.navigate(['/dashboard']),  // sucesso
    error: (err) => {
      this.errorMessage.set(err.error?.message ?? 'Credenciais inválidas.');
      this.loading.set(false);
    },
  });
}

⚡ 10. Signals vs RxJS — por que usar os dois

SignalObservable (RxJS)
Usado para Estado da UI: loading, errorMessage, user, mode Operações assíncronas: chamadas HTTP
Leitura loading() — com parênteses .subscribe() ou async pipe
Escrita loading.set(true) Emitido pelo Observable (não você)
Cancelamento Automático pelo Angular Precisa de unsubscribe() ou takeUntilDestroyed()
Por que não usar só Signals? Signals não suportam fluxos assíncronos (retry, catchError, switchMap). RxJS ainda é o padrão para HTTP.
Regra prática: use Signal para estado local da UI e Observable para comunicação com a API. O tap() do AuthService é a ponte: o HTTP é Observable, mas após a resposta ele atualiza o Signal.
