🔀 Fluxo completo da chamada de Login

Cliente Postman
→
Gateway (YARP) :5000 rota: bff-route
→
BFF :5223 LoginEndpoint
→
AuthService :5290 POST /auth/login

Como o Gateway transforma a rota

// appsettings.json do Gateway
"bff-route": {
  "ClusterId": "bff-cluster",
  "Match": { "Path": "/bff/{**catch-all}" },
  "Transforms": [
    { "PathPattern": "{**catch-all}" }   // remove o prefixo /bff
  ]
}
  • Postman envia POST /bff/accounts/login → Gateway na porta 5000.
  • Gateway faz match na rota bff-route (/bff/{**catch-all}). O transform remove o prefixo /bff.
  • BFF recebe POST /accounts/login na porta 5223. O LoginEndpoint processa e chama o AuthServiceClient.
  • AuthService recebe POST /auth/login na porta 5290 e retorna o JWT.
  • A resposta percorre o caminho inverso até o Postman.

🟡 FORA DO DOCKER — Desenvolvimento local

Certifique-se de que Gateway, BFF e AuthService estão rodando antes de chamar o Postman.

Request — Via Gateway (recomendado)

CampoValor
MétodoPOST
URLhttp://localhost:5000/bff/accounts/login
Content-Typeapplication/json

Body (raw JSON)

{
  "email": "usuario@email.com",
  "password": "suaSenha"
}

Request — Direto no AuthService via Gateway (sem BFF)

CampoValor
MétodoPOST
URLhttp://localhost:5000/auth/login
Content-Typeapplication/json
A rota auth-route do Gateway encaminha diretamente para o AuthService (:5290) sem passar pelo BFF. Útil para testar o AuthService isoladamente.

🐳 COM DOCKER — Infra no container

O docker-compose.yml atual sobe apenas a infra: Postgres :5432, Redis :6379, Kafka :9092 e Kafka UI :8085. Os serviços .NET continuam rodando localmente — a URL do Postman é idêntica à anterior.

Subir a infra

# No terminal, dentro de bandhub-infra/docker
docker compose up -d

Chamada no Postman (idêntica ao cenário local)

CampoValor
MétodoPOST
URLhttp://localhost:5000/bff/accounts/login
Content-Typeapplication/json

Se os serviços .NET também fossem dockerizados

Neste cenário hipotético, dentro da rede Docker os serviços se comunicariam pelo nome do serviço definido no compose (ex: http://bandhub-authservice:5290). Os appsettings.json do BFF e do Gateway precisariam ter variáveis de ambiente sobrescrevendo os localhost para os nomes dos containers. Para o Postman (que está fora da rede Docker), a URL continuaria sendo localhost:<porta_exposta>.
